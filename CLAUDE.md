# МЭШ — Оценка учебных умений

Chrome MV3 расширение для `school.mos.ru`: в журнале учителя проходит по всем
ученикам и в форме «Оценка учебных умений» ставит «Почти всегда» во всех пунктах,
затем сохраняет. Родственный проект — `ivangusarov386-lab/mesh` («Помощник
учителя»); правила и проверенные приёмы взяты оттуда.

## Маршрут в МЭШ (со скриншотов пользователя)

Журнал предмета → клик по ФИО ученика → попап «Информация об учащемся» →
кнопка «Оценить учебные умения» → боковая панель «Оценка учебных умений»
(подзаголовок «<ФИО полностью> · 1 модуль»), группы «Самоорганизация»,
«Самообразование», … — в каждом пункте варианты «Почти никогда / Редко /
Часто / Почти всегда / Затрудняюсь ответить» → «Сохранить» / «Отмена».
В форме написано: оценка «проводится по всем вашим предметам сразу», поэтому
достаточно пройти один журнал класса.

## Как устроен `src/skills-autofill.js`

- Элементы формы и попапа ищутся **по тексту** (TreeWalker по текстовым узлам),
  а не по CSS-классам — классы school.mos.ru генерируются сборкой.
- Строки учеников: `tr` с `[data-test-component^="markCell-"]` или
  `[data-test-component^="studentCellInfoComments-"]`, ФИО — `span[title]`
  (проверенный паттерн из проекта mesh).
- Клик — `humanClick()`: плавная прокрутка к элементу, если он вне видимой
  области; свой указатель (`#mesh-skills-cursor`) едет к случайной точке
  внутри элемента; наведение → pointer/mouse down/up → `click()`. Между
  пунктами формы 0,2–0,5 с (изредка 0,45–0,9 с), перед «Сохранить» 0,35–0,8 с.
- Скорость: переключатель «Спокойно / Быстро / Турбо» (`SPEEDS`, множитель
  1 / 0,45 / 0,22, хранится в `meshSkillsSpeed`, по умолчанию «Быстро»). Все
  «человеческие» паузы идут через `pace(ms, min)` — новые паузы тоже только
  через неё. Ожидания загрузки (`waitFor`/`waitStable`) от режима НЕ зависят:
  они защищают от слёта отметок, не ускорять их ради скорости. Пожелание
  пользователя: «быстрее меня», но движения человеческие.
- Уже оценённый ученик: в попапе вместо «Оценить учебные умения» кнопка
  «Повторно оценить учебные умения» — сразу закрываем попап и идём дальше
  (статус «уже оценён»). Попап ищется по заголовку + любой из кнопок
  («Оценить…», «Повторно оценить…», «Подробнее»), иначе у оценённых он
  не находился и каждый ученик ждал таймаут.
- Панель расширения по умолчанию слева внизу (справа выезжает форма МЭШ);
  перетаскивается за шапку и «таблеткой» (`makeDraggable`): захват указателя
  сразу на `pointerdown` + `preventDefault` (иначе при быстром рывке с
  маленькой «таблетки» движения терялись), порог 4px отличает перетаскивание
  от клика-сворачивания. Позиция — `meshSkillsPos` `{left, top}`,
  `clampPanel()` держит панель в окне (resize, сворачивание, рост содержимого
  через ResizeObserver).
- Ответ для всех пунктов выбирается в панели («Ответ»: Почти никогда / Редко /
  Часто / Почти всегда / Затрудняюсь ответить — одинаковы во всех пунктах),
  `targetOption`, хранится в `meshSkillsAnswer`; по умолчанию «Почти всегда».
  Число пунктов в форме считается по «Почти никогда» (`ANY_OPTION`).

## Дизайн панели

- Все цвета, радиусы, тени — токены `--msa-*` в начале `skills-autofill.css`;
  хардкод цветов в остальных правилах не допускается.
- Структура: шапка (знак + «Учебные умения» + подзаголовок; клик по шапке
  сворачивает в «таблетку») → раздел «Классы» → раздел «Этот журнал» →
  ход работы (счётчик, «Стоп», статус с цветной полосой, прогресс-бар,
  лента учеников с цветными точками) → «Результаты по классам» (карточки
  журналов с чипами сохранено/уже/ошибки).
- Иерархия кнопок: `msa-btn--primary` (заливка) — только «Все мои классы» и
  «Начать»; `msa-btn` (обводка) — «Заполнить и сохранить»; `msa-btn--ghost` —
  вспомогательные «Проверка»/«Открытая форма»; `msa-btn--danger` — «Стоп»,
  «Очистить». Кнопки собираются через `button({...})`.
- Иконки — inline SVG из констант `ICONS` (`icon(name)`), не эмодзи. Через
  `innerHTML` идут ТОЛЬКО эти константы; данные со страницы — `textContent`.
- «Стоп» виден только во время работы (класс `.msa-busy` на панели).
- Раскрывашки — `aria-expanded` + `.msa-chevron` (поворот на 90°).
- `prefers-reduced-motion` отключает анимации.
- Защиты: сверка фамилии в шапке формы с кликнутой строкой; если отмечено
  меньше пунктов, чем вопросов, или «Сохранить» не сработала — останов с
  открытой формой (fatal), а не тихий переход к следующему ученику.
- Форма МЭШ может открыться пустой и пересобраться, когда догрузятся данные
  ученика, — отметки, поставленные до этого, слетают (реальный баг v0.2:
  писало «уже было заполнено», а в МЭШ пусто). Поэтому: перед заполнением и
  после него ждём, пока DOM успокоится (`waitStable`), статистику отметок
  считаем заново по свежему `findForm()`, при слёте — заполняем повторно.
- «Уже было заполнено» — только если форма ОТКРЫЛАСЬ уже заполненной. Если
  «Сохранить» неактивна после наших кликов — форма закрывается и открывается
  заново для перепроверки; не подтвердилось — останов с ошибкой.
- **Все мои классы** — раскрывающийся блок под кнопкой (`togglePicker` →
  `renderPicker`): галочка «Все классы», галочка на параллель (по ведущим
  цифрам `classLabel`, состояние «частично» через `indeterminate`) и на каждый
  класс. Список классов кэшируется в `meshSkillsClasses` `{list, at}`, выбор —
  в `meshSkillsSelection` (массив id), поэтому выбирать можно с любой страницы
  журнала; «Загрузить список»/«обновить» → переход на «Мои классы»
  (`loadClassesFromMyPage`, батч `status: "picking"`) и обратно в выбор.
  Запуск — `startAllClasses` → `resumeBatchIfRunning`. Список классов — карточки
  `[data-test-component="journalCardRoute"]` со ссылкой `/journal/my/<id>` на
  странице `/teacher/study-process/journal/my` (свёрнутые параллели
  раскрываются кликом по `h6` секции `journalListSection-*`) — проверенный
  способ из mesh `class-auto-loader.js`. Обход идёт в отдельной ФОНОВОЙ
  вкладке: `startAllClasses` → сообщение `start-worker` → service worker
  открывает неактивную вкладку и пишет её `tabId` в батч; content script
  через `whoami` понимает, что он рабочий (`isWorker`). Остальные вкладки —
  наблюдатели: ход работы рабочая вкладка шлёт в `meshSkillsProgress`
  `{text, tone, fraction, log}`, панели слушают `chrome.storage.onChanged`.
  «Стоп» из любой вкладки → `status: "stopped"` → рабочая вкладка доделывает
  шаг и закрывается; закрыли её руками — service worker помечает обход
  остановленным. В скрытой вкладке Chrome замедляет `setTimeout` (≥1 с, через
  5 мин — раз в минуту), поэтому `sleep()` при `document.hidden` ждёт через
  сообщение `sleep` в service worker, а `waitStable` опрашивает через `sleep`,
  без цепочек таймеров. Без `chrome.runtime` (макет) — старый режим в той же
  вкладке. Журнал открывается в рабочей вкладке по
  `/teacher/study-process/journal/grade/<id>?logon_source=teacher_mentor_journals`;
  состояние — `chrome.storage.local` `meshSkillsBatch` `{status: picking|running|
  done|stopped, queue, index, visits}`, после перезагрузки страницы скрипт
  продолжает с текущего журнала. Не тот журнал открылся — возврат, после 3
  попыток класс пропускается.
- «Форма закрылась сама» / «в форме не найдено ни одного пункта» (живой баг
  v0.9): по скриншоту v0.9.1 форма на деле ОТКРЫТА и частично заполнена —
  `findForm()` на миг возвращал null (МЭШ перерисовывает форму). Поэтому одна
  неудачная проверка формы ничего не значит: везде, где форма нужна,
  `findForm() || await waitForForm()` (ждёт до 4 с); `findForm` с запасным
  путём «заголовок + варианты ответа», если кнопку «Сохранить» не нашли.
- «Почти все со 2-й попытки» и «в форме не найдено ни одного пункта» (живой
  баг v0.9.2): гипотеза — после закрытия МЭШ оставляет форму прошлого ученика
  в DOM спрятанной/без содержимого, и бралась она (первая по порядку). Поэтому
  `isVisible` учитывает `visibility:hidden`, а `findForm` собирает ВСЕ формы
  (`formCandidates`) и берёт ту, где есть варианты ответа, из таких —
  последнюю. В сообщении «форма открылась с N-й попытки» теперь снимок
  `describePage()` первой попытки (в т.ч. «форм видно: N») — по нему
  подтвердить/опровергнуть гипотезу.
- Диалог МЭШ «Выход без сохранения» («Назад» / «Выйти без сохранения»)
  появляется после «Отмены», если в форме есть отметки. Мы бросаем форму
  только намеренно → `cancelForm()` подтверждает «Выйти без сохранения»
  (`confirmDiscardIfAsked`), `cleanupAfterError` закрывает и оставшийся диалог.
- Переоткрытие формы: `openFormFor`
  открывает попап → «Оценить…» → форму до 3 раз; при пропаже формы пишет
  `describePage()` (есть ли заголовок в DOM, скрыт ли, сколько «Сохранить»,
  открыт ли попап, фоновая ли вкладка) — этот снимок попадает в сообщение
  ошибки в результатах, по нему и искать причину. Переключатель «В фоновой
  вкладке» (`meshSkillsBackground`, по умолчанию вкл.) — выключить, если в
  фоне сбоит: обход пойдёт в текущей вкладке.
- Ошибка по ученику обход НЕ останавливает: форма закрывается «Отменой»,
  ученик пишется в результаты. Журнал бросаем, если форму не удалось закрыть
  или 3 ошибки подряд (системная поломка). В режиме «Проверка на 1 ученике»
  форма остаётся открытой.
- Результаты — `meshSkillsResults` `{<journalId>: {title, classLabel, note,
  students: {<ФИО>: {status, message, at}}}}`, пишутся после КАЖДОГО ученика
  (и в одиночном журнале, и в обходе классов), повторный прогон обновляет
  статус ученика. В панели «Результаты по классам»: по журналу счётчики,
  список ошибок, ссылка «Открыть журнал», CSV-отчёт (с `csvValue` против
  формульной инъекции, как в mesh).
- В регэкспах с кириллицей не использовать `\b` — в JS он ASCII-only
  (`/^Журнал\b/` не совпадает с «Журнал Физ…»), писать `\s`.
- Ручное управление из консоли (контекст content script):
  `window.__MESH_SKILLS_AUTOFILL__.runAll({ limit: 1, save: false })`.

## Что ещё НЕ проверено вживую

Точная DOM-разметка формы (MUI radio в `<label>` или что-то своё), какой
элемент строки открывает попап (кликаем `span[title]`, затем его `td`),
вид крестика попапа (первая кнопка без текста). Если что-то не находится —
смотреть вживую в DevTools и присылать разметку, **не гадать**.

## Проверка перед коммитом

`node --check src/skills-autofill.js` и прогон в Chromium (Playwright,
`executablePath: /opt/pw-browsers/chromium-1194/chrome-linux/chrome`) на
макете страницы с журналом, попапом и формой — макет держать в scratchpad,
не в репозитории. Для обхода классов — сквозной тест с НАСТОЯЩИМ
расширением: `launchPersistentContext` с `--load-extension`, а
`context.route('https://school.mos.ru/**')` отдаёт макеты «Мои классы» и
журналов (content script тогда внедряется как на живом сайте). Ограничение
стенда: вкладку, созданную `chrome.tabs.create`, `context.route` не успевает
перехватить на первой загрузке (chrome-error) — в тесте делать ей `goto` на
тот же адрес.
